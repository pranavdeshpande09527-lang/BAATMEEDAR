# Baatmeedar — README Prompt

Update the repository README so a newcomer can run and assess the project honestly.

## Required sections

Product purpose and five-stage workflow; current implementation status; static frontend setup/run instructions; mock-mode caveat; supported input UX; intended API contract; architecture links; configuration template and secret rules; provider/database decisions required; testing; deployment status; limitations; contribution guidance; and demo instructions.

## Accuracy rules

State that the committed frontend currently renders mock results while `USE_MOCK = true`; do not claim live Gemini, Tavily, Groq, Grok/xAI, transcript, auth, database, or deployment behavior without tested code. Use the verdict terms `supported`, `contradicted`, and `inconclusive`, explain evidence limitations, and distinguish Groq from Grok/xAI.

## Acceptance

A reader can reproduce the current prototype, identify every missing credential/decision, and understand that the tool supports evidence inspection rather than professional or guaranteed fact checking.
