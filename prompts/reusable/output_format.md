# Baatmeedar — Reusable Implementation Output Format

For implementation work, respond in this order:

1. Outcome and brief scope.
2. Assumptions, decisions, and dependencies.
3. Changed files/modules and contract/schema changes.
4. Safety, provenance, and compatibility notes.
5. Tests run and results, including untested credential-dependent paths.
6. Remaining limitations, rollout/rollback notes, and next required decision.

Never state that a provider, source, database, deployment, or result is live unless it was actually configured and verified. State mock/deferred behavior plainly.
